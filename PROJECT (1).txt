from datetime import datetime

router = APIRouter(
    prefix="/alerts",

# Temporary in-memory storage (later we’ll use DB)
alerts = []

@router.get("/")
def get_alerts():
    return alerts

@router.post("/")
def create_alert(type: str, message: str, severity: str = "info"):
    global alert_id_counter
    alert = {
        "id": alert_id_counter,
        "type": type,
        "message": message,
        "severity": severity,
        "timestamp": datetime.utcnow().isoformat()
    }
    alerts.append(alert)
    alert_id_counter += 1
    return alert

from fastapi import APIRouter
from pydantic import BaseModel
from datetime import datetime
from routers import alerts  # 👈 import alerts router

router = APIRouter(
    prefix="/logs",
    tags=["Logs"]
)

# temporary in-memory storage
logs_db = []

class Log(BaseModel):
    id: int
    source: str
    message: str
    severity: str
    timestamp: datetime

@router.get("/")
def get_logs():
    return {"logs": logs_db}

@router.post("/")
def add_log(log: Log):
    # ✅ Save the log
    logs_db.append(log.dict())

    # 🚨 Auto-create alert if severity is critical
    if log.severity.lower() == "critical":
        alert = {
            "id": len(alerts.alerts) + 1,
            "type": "Critical Log Alert",
            "message": f"[{log.source}] {log.message}",
            "severity": "critical",
            "timestamp": datetime.utcnow().isoformat()
        }
        alerts.alerts.append(alert)

    return {"message": "Log added successfully", "log": log}

Good question 👍
The “422 Unprocessable Content” error in FastAPI usually happens when the JSON body you send doesn’t match the Pydantic model your route expects.

In your case, the POST /logs endpoint expects this model 👇

class Log(BaseModel):
    id: int
    source: str
    message: str
    severity: str
    timestamp: datetime


That means your request must include all these fields, with the correct types.
⚠️ If one is missing or has the wrong format, FastAPI returns 422.

✅ Example of a correct request body for POST /logs
{
  "id": 1,
  "source": "Firewall",
  "message": "Intrusion detected",
  "severity": "critical",
  "timestamp": "2025-10-18T22:25:00"
}


🕒 The timestamp must be in ISO 8601 format:

YYYY-MM-DDTHH:MM:SS


✅ Example: 2025-10-18T22:25:00

🧠 Tips to avoid this error:

Don’t use wrong field names (e.g., time instead of timestamp).

Don’t leave out required fields.

Make sure the timestamp format is correct (don’t just write “now” or “2025/10/18”).

Use Swagger UI (http://127.0.0.1:8000/docs
) — it helps you fill the body correctly.

🛠 Optional Improvement (if you want to make it easier)

You can make id and timestamp auto-generated instead of required.
For example:

from pydantic import BaseModel, Field
from datetime import datetime

class Log(BaseModel):
    id: int = Field(default_factory=int)
    source: str
    message: str
    severity: str
    timestamp: datetime = Field(default_factory=datetime.utcnow)


Or even simpler, don’t include id in the request at all — just generate it on the server side when adding the log.

👉 That way you can send:

{
  "source": "Firewall",
  "message": "Intrusion detected",
  "severity": "critical"
}


and the backend will fill in the rest ✅
